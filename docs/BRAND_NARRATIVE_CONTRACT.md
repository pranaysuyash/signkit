# SignKit brand narrative contract

Date: 2026-08-12
Owner: CDO mode led by the solo operator and agents
Status: Working contract for public-surface decisions

## Strategic position

SignKit makes sensitive signed-document work feel controlled, local by
default, and finished in one calm workflow.

This is a product-system position, not a visual slogan. Every public surface
must connect the promise to a real capability, evidence, transaction boundary,
and post-purchase expectation.

## Narrative model

### The customer situation

People repeatedly move signatures from signed documents into PDFs. The work is
small but consequential: it involves sensitive files, visual accuracy, and a
need to finish without learning a large document platform.

### The job SignKit performs

SignKit helps a customer extract, clean, save, and place signatures on PDFs
locally by default.

### The proof we are allowed to use

- The extraction and cleanup workflow in the release bundle.
- The reusable local signature Vault.
- PDF placement and export capabilities in the release bundle.
- The documented privacy boundary: core extraction and PDF work run locally by
  default; checkout receives purchase and delivery information.
- The one-time Personal pricing and qualified update boundary.
- The current refund policy, only while the legal documents remain aligned.

These are capability and policy proofs. They are not customer counts,
benchmarks, performance promises, ratings, or regulated-signature guarantees.

### The boundary we must make visible

SignKit is local-first, not an absolute offline or zero-network guarantee.
Checkout, licensing, updates, and enquiry handling have their own boundaries.
Public copy must say what happens locally and what information is sent to an
external provider.

## Voice principles

1. Precise before impressive. Describe the job and boundary before adjectives.
2. Calm before urgent. Reduce handling anxiety instead of manufacturing fear.
3. Useful before clever. Use concrete verbs: extract, clean, save, place, export.
4. Qualified before absolute. Say "locally by default" when that is the
   verified boundary.
5. Premium through control. Confidence should come from clarity, not inflated
   proof or visual noise.

## Approved message pattern

Use this sequence for acquisition and trust sections:

1. Situation: sensitive signed documents create repetitive work.
2. Outcome: extract once, keep a reusable local signature, and place it on a
   PDF.
3. Proof: show the real workflow and name the local-processing boundary.
4. Transaction: state the one-time price, provider state, refund policy, and
   update boundary.
5. Follow-through: explain what the customer receives and where support goes.

## Phrases to use and avoid

| Use | Avoid |
| --- | --- |
| local processing by default | 100% offline |
| secure checkout through the configured provider | Dodo delivers your order |
| one-time Personal licence | lifetime access to everything |
| minor updates within the purchased major version | every future major release |
| example operator contexts | trusted by thousands |
| product preview | benchmark or guaranteed speed |

## Public-surface acceptance contract

A public page is ready only when:

- It is the canonical root or is explicitly redirected to it.
- Every customer-facing claim is represented in the launch-claim registry.
- Its tone follows this narrative without introducing stronger promises.
- Its checkout uses the canonical provider configuration and telemetry.
- Its legal and refund language matches the current legal documents.
- Its evidence tier and required reviewer are recorded.

The current canonical implementation is `index.html`. The route, claim, and
checkout authorities are documented in
`docs/launch_claims/public_surface_map.md`.

## Review decisions and solo-operator handling

- Solo-operator review of refund, licence, privacy, and provider wording before
  a public release. External legal review is not a default requirement and is
  only opened if a specific customer, payment provider, platform, or regulatory
  obligation requires it.
- Product confirmation that the release bundle supports every named workflow.
- Analytics confirmation that checkout intent and purchase completion can be
  joined without introducing personal data into event labels.

Use qualified, evidence-backed wording when an external reviewer is not
available. Do not turn a copy uncertainty into a certification project.
